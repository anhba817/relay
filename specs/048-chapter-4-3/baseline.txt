T004 — THE TEMPLATE THIS CONSUMER MAY NOT REUSE
-------------------------------------------------
`runtime.ts:195` calls `claimEvent(db, durable, parsed!.id, effect)`. The function itself,
read rather than cited:

    return db.transaction(async (tx) => {
      const claimed = await tx
        .insert(consumedEvents)
        .values({ consumer, eventId })
        .onConflictDoNothing({ target: [consumedEvents.consumer, consumedEvents.eventId] })
        .returning({ eventId: consumedEvents.eventId });
      if (claimed.length === 0) return "duplicate";
      await effect();
      return "handled";
    });

A **PostgreSQL transaction**. Constitution III forbids it on this path, and the runtime's own
header says it exists because *"a future consumer forgets to dedupe → double webhooks /
double metering"*. This is that consumer.

T011 / T011a / T012 — THE TABLE, AND BOTH GUARDS FIRING
---------------------------------------------------------
    engine         ReplacingMergeTree

Each guard was tested against the failure it exists for, and they are different failures:

    absent `ts`      Code: 469. Constraint `ts_is_real` for table
                     relay_analytics.webhook_attempts ... violated
    renamed key      Code: 117. Unknown field found while parsing JSONEachRow
                     format: attempted_at
    correct row      inserted · ts = 2026-09-14 10:00:00.500, milliseconds preserved

`input_format_skip_unknown_fields = 0` catches the rename; it does **not** catch the absent
field, which takes the epoch default without complaint. The constraint catches that one.
`date_time_input_format = best_effort` is what parses the ISO-8601 string at all.

**The probe row was truncated before anything else was counted** — 0 rows afterwards.
