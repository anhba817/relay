------------------------------------------------------------

**FIVE store containers, not four.** clickhouse, mailpit, nats, postgres, redis —
mailpit is one of them and a lane without it fails on `ECONNREFUSED :8025`.
`--wait` matters: without it the suites race container readiness.

**AND A NAME COLLISION NOBODY HAD NOTICED.** Grepping for the route turned up two
unrelated hits: `services/api/src/db/schema.ts:76` and
`services/api/src/db/catalogue.ts:57` both carry a table called **`memberships`**,
described there as *"joins humans to organisations, above the environment level"*
— chapter 3.1's platform-side table. The route this chapter revives returns
**channel** memberships for one user, which is a different concept one boundary
down. Neither is wrong and they will read as the same word in a grep; the module
and its tests should say `channel_ids` where they can, as the contract already does.

T008 — the fixture's assertion, read rather than its path:

    services/api/src/tenancy/signup.itest.ts:285-296
    POSTs /internal/memberships with no credential, asserts status !== 200
    and that the body does not contain "organisation"

**A GET-only revival leaves it standing**, because a GET-only route answers a POST
with 404. What breaks it is registering `ALL`, adding a POST twin, or answering an
unauthenticated caller. Research R4's first draft said the revival would break this
and analysis pass 2 corrected it; this is the confirmation.

**229.41 s is one draw, not the distribution.** Chapter 3.19's close-out battery put
the mean at 228.18 with stdev 1.41 over eighteen green runs, so this sits half a
standard deviation high and means nothing on its own. It is the before-number the
close-out battery is compared against, and it is a single sample by design — the
twenty-run version costs eighty minutes and belongs at the end.

**THE GATEWAY PACKAGE IS 45.60 s AND THAT IS ONE FILE.** 28 cores against 8 files, so
all run concurrently and the package's clock is its slowest — `presence.itest.ts`,
which measured 45.2 s standalone at chapter 3.19's close. This feature adds a ninth
file to that package. Under 45 s it costs the lane almost nothing; over, it becomes
the pacesetter and every second is a lane second. T041 budgets it at 40, of which
about 18 is waiting FR-RTM-10's own five seconds three times over.

THE VIOLATION, STILL ASSERTED (T004)
------------------------------------------------------------

    npx vitest run --config vitest.integration.config.mts -t "FR-RTM-10"
    Test Files  1 passed | 7 skipped (8)
    Tests       1 passed | 102 skipped (103)      6.44 s

`session.itest.ts:677` — *"keeps delivering to a member who was REMOVED while
connected (FR-RTM-10)"* — passes, and **a pass is the violation.** It waits out the
clause's own 5,500 ms and asserts the frame the clause forbids does arrive. Its
closing comment is this chapter's instruction: *"change this to `.rejects` on the day
a re-read exists."*

**Recording which red it is NOT.** It is green today and it must go red the moment
the module is wired and before the assertion is inverted — a red there means the
removal reached the gateway. If it stays green after wiring, nothing arrived and the
inversion would pass for the wrong reason.
