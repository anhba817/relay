T001b · Two consumers, two addresses, because the host is in the signature
------------------------------------------------------------------------------
  `presign.ts` signs `X-Amz-SignedHeaders: host` with `host:${host}` in the
  canonical request, so a URL signed for one origin is refused at another. One
  `endpoint` field cannot serve both consumers once they disagree, and they have
  agreed until now only because every lane runs the api as a host process.

    StoreConfig.endpoint          where the CLIENT reaches the store — signed
                                  into the upload URL
    StoreConfig.internalEndpoint  where THIS SERVICE reaches it — the probe and
                                  ensureBucket. Defaults to `endpoint`.

  The default is what keeps every existing lane unchanged: unset, the two are
  the same string and nothing has to know the field exists.

  compose.yaml now sets both:
    RELAY_MINIO_ENDPOINT          http://localhost:9100
    RELAY_MINIO_INTERNAL_ENDPOINT http://minio:9000

  AFTER, the same request against a rebuilt and force-recreated api:

    POST localhost:4000/v1/media  ->  201
      media_id  9940ad63-…
      state     pending
      upload_url signed for http://localhost:9100

    PUT that URL from the host    ->  200        2,097,152 bytes

  SC-012 discharged: a slot from the COMPOSED api, and a URL usable from outside
  the compose network. tsc --noEmit EXIT 0; 39 unit files, 409 tests, green.

  store.test.ts needed two edits and both are the finding in miniature: the
  suite redirects the store to a fake server and overrode `endpoint` alone,
  which after the split would have pointed the fake at the client's address and
  left the probe talking to the real store.

THE ARM, AND WHAT THE COMPILER ASKED FOR
------------------------------------------------------------------------------
  `.refine(() => false)` and its `protocolCode` params are gone; `media_id` is
  `z.uuid()` where it was `z.string().min(1)`.

  ONE PERMISSIVE ELEMENT, NOT FOUR COPIES. `forwardedAttachmentSchema` is
  exported once and used by all five forwarding readers. The strict union is
  unchanged and still refuses an arm it does not know, which is what a request
  schema is for.

  AND THE COMPILER NAMED SEVEN SITES, WHICH IS THE `attachments: required`
  COMMENT EARNING ITS KEEP. Making the schemas permissive left hand-written
  types narrow, and `tsc` listed every place a forwarded value met a strict one:

    consumer/runtime.ts:166      OutboxEvent's attachments was Attachment[]
    session.ts:399, 1377         send(frame: Frame) — the outbound relay
    session.ts:1365              highWaterMarks(… messages: Message[])
    session.ts:1628              fanout.publish(message: Message)

  EACH ONE WAS FIXED BY WIDENING THE TYPE, NOT BY CASTING. A consumer really can
  be handed an arm its binary does not know — that is what the schema now says —
  and a type that denied it would move the lie one layer in. Two of them got
  something better than a wider type:

    highWaterMarks   typed by what it READS: `{ messages: { seq: number }[] }`.
                     It touches one field and never an attachment.
    send             takes `RelayedFrame`, a new type: the published `Frame`
                     contract is unchanged, because what is happening is not
                     "this platform intends to send unknown arms" but "two
                     versions of the server briefly disagree", and the honest
                     place to say that is the type of the process between them.

**AND THE TASKS' OWN PREMISE HAD MOVED UNDER THEM.** T017b, T017e and T017g each
said to test with `{ "type": "media", "media_id": "<uuid>" }` and to run it red
"against the arm as it stands today". That was the right probe when the media arm
REFUSED. This chapter makes it accept — so a media attachment now parses under the
strict union too, and every one of those tests would have passed with or without
the permissive reader. **They would have asserted nothing.** What discriminates
the two is an arm from a writer NEWER than this binary, so each test sends
`{ type: "audio_clip", clip_id, duration_ms }` beside the media arm, and the red
probe reverts the READER rather than the arm.

  A fourth premise held: the negative control still passes. A payload that is not
  a message (`seq: -1`) is still dropped. Permissive about the ARM is not
  permissive about being an attachment — `forwardedAttachmentSchema` still
  refuses a value with no `type`, and the pair of tests is what says so.

The predicate: one query, the difference taken in order
------------------------------------------------------------------------------
  `assertAttachableMedia`, inside `sendMessage`'s transaction, after the ban,
  the channel and the quota and before the insert. Three clauses in the clause's
  own order: environment, uploader, state.

  ONE `IN` AND NOT N. Up to ten round trips inside a write transaction for a
  question one query answers. What it costs is that "which one failed" becomes a
  set difference — and the difference preserves POSITION, because the refusal's
  field is `attachments.<n>.media_id`.

  T020a · `senderMustBeBot` IS REUSED AND THE ALTERNATIVE IS THE VIOLATION. The
  predicate needs one fact — whether the caller is an application credential —
  and `sendMessage` already carries it under a name about the sender. A second
  boolean called `callerIsApplication` would read better here and is exactly what
  research R5 forbids: *"the repository must not learn what a credential is."*

  `state IN ('pending','ready')` IS WRITTEN IN FULL AND ONE ARM CANNOT OCCUR.
  The CHECK constraint is `state = 'pending'`. The clause names both, so the
  predicate names both, and whoever builds the scanner does not have to find it.

T031 · The send's latency, and the first measurement was the pacing
------------------------------------------------------------------------------
    no attachment          p50  7.452   p95  9.490   mean 7.528

  WHAT IT IS A MEASUREMENT OF: one indexed lookup inside a transaction, against a
  lane whose `media_objects` holds a few hundred rows. It is not a production
