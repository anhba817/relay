# Implementation Plan: Next.js Tutorial Repository Setup

**Branch**: `main` (no feature branch — see Notes) | **Date**: 2026-07-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-nextjs-tutorial-setup/spec.md`

## Summary

Create the `relay-tutorial` repository — the application home for the *Building Relay*
tutorial series — as a fresh Next.js 16.2.12 app generated by the official CLI, themed
with the tweakcn **Violet Bloom** shadcn style (light + dark), hosted publicly under
`anhba817`, and registered as a git submodule of this repo at root path
`relay-tutorial/`, pinned to an exact revision. Scaffold + theme only; no tutorial
content. Full decisions and verified facts in [research.md](./research.md).

## Technical Context

**Language/Version**: TypeScript 5.x (as generated by create-next-app 16.2.12), Node.js 22 (local: v22.20.0)

**Primary Dependencies**: Next.js 16.2.12 · React 19 · Tailwind CSS v4 · shadcn CLI 4.16.0 · tweakcn Violet Bloom registry item · next-themes · Google fonts via `next/font` (Plus Jakarta Sans, Lora, IBM Plex Mono)

**Storage**: N/A (static scaffold, no data layer)

**Testing**: `pnpm build` as the smoke gate + the quickstart validation scenarios (visual light/dark check); no test framework is added — the scaffold ships none and adding one is out of scope (FR-003)

**Target Platform**: Local dev server (evergreen browsers); GitHub-hosted public repository

**Project Type**: Standalone web application repository, linked as a git submodule of `relay`

**Performance Goals**: None feature-specific — dev server must start and render the home page without errors (FR-006)

**Constraints**: Scaffold purity boundary per research R8 (only theme/docs/config changes); versions pinned at creation (spec edge case, tutorial risk T3); repo creation under `anhba817` requires a one-time user action (research R6)

**Scale/Scope**: One repository, one themed page, one submodule link; ~5 files modified beyond the scaffold

**Structure Decision**: Two-repository layout — the scaffold lives entirely inside the
new `relay-tutorial` repository (standard create-next-app app-router layout, no `src/`
dir); the parent `relay` repo gains only `.gitmodules` and the pinned gitlink entry.
No changes to `docs/`, `.specify/`, or any existing parent content.

## Implementation Flow (input to /speckit-tasks)

1. **Scaffold** (FR-001/002/003): run the R2 command in a temp location or directly;
   verify `next` resolves to 16.2.12; initial commit = pure CLI output.
2. **Theme** (FR-005): shadcn init → add Violet Bloom registry URL → font wiring in
   `layout.tsx` → ThemeProvider → restyled `page.tsx` with Button; commit.
3. **Docs** (FR-006/007): README with purpose, relationship, install/run, submodule
   init instructions; commit.
4. **Host** (FR-001, research R6): ⚠ one-time user action to create the empty public
   repo `anhba817/relay-tutorial` (gh auth login for anhba817, or github.com/new);
   then push over SSH.
5. **Link** (FR-004): `git submodule add` in parent, commit `.gitmodules` + gitlink.
6. **Validate** (SC-001..004): execute [quickstart.md](./quickstart.md) scenarios.
