# Feature Specification: Next.js Tutorial Repository Setup

**Feature Branch**: `001-nextjs-tutorial-setup`

**Created**: 2026-07-29

**Status**: Draft

**Input**: User description: "Set up Next.js repository that will be use for the tutorial. The repo name is relay-tutorial and is a submodule of this repo. The repo must use the latest Next.js version and created by Next.js CLI. Use the Violet Bloom theme"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Scaffold the tutorial application repository (Priority: P1)

As the tutorial author, I need a fresh, standalone repository named `relay-tutorial`
containing a newly generated Next.js application, so that the *Building Relay* tutorial
(docs/07-tutorial-plan.md) has a clean, independently versioned home for its application
code from day one.

**Why this priority**: Nothing else in this feature has value without the repository and
the generated application existing. This is the foundation every tutorial chapter builds
on.

**Independent Test**: Can be fully tested by opening the `relay-tutorial` repository,
confirming it is a freshly generated Next.js application on the latest stable version,
and starting it locally to see the default page render without errors.

**Acceptance Scenarios**:

1. **Given** the `relay-tutorial` repository exists, **When** its dependency manifest is
   inspected, **Then** it declares the latest stable Next.js version available at
   creation time.
2. **Given** a developer has cloned `relay-tutorial` and installed dependencies,
   **When** they start the development server with the standard documented command,
   **Then** the application serves its home page without errors or warnings that block
   startup.
3. **Given** the repository history, **When** the initial commit is inspected, **Then**
   its contents correspond to output generated by the official Next.js scaffolding tool
   (not hand-assembled files).

---

### User Story 2 - Link the tutorial repository as a submodule (Priority: P2)

As a maintainer of the `relay` repository, I want `relay-tutorial` registered as a git
submodule of `relay`, pinned to an exact revision, so that the documentation repo and the
tutorial application stay linked and anyone browsing `relay` can discover and check out
the matching tutorial code.

**Why this priority**: The link makes the tutorial code discoverable and version-locked
from the main repo, but the tutorial app is independently useful without it.

**Independent Test**: Can be fully tested by performing a fresh clone of `relay` with
submodule initialization and confirming the `relay-tutorial` directory is populated with
the application at the pinned revision.

**Acceptance Scenarios**:

1. **Given** a fresh clone of the `relay` repository, **When** submodules are
   initialized and updated, **Then** the `relay-tutorial` directory contains the
   tutorial application at the exact revision recorded by the parent repository.
2. **Given** the `relay` repository, **When** its submodule configuration is inspected,
   **Then** it records the `relay-tutorial` repository location and path.
3. **Given** a clone of `relay` where submodules were NOT initialized, **When** the
   developer follows the documented setup instructions, **Then** the instructions
   explain how to initialize the submodule.

---

### User Story 3 - Apply the Violet Bloom theme (Priority: P3)

As the tutorial author, I want the application styled with the Violet Bloom theme so
that every screenshot and demo built throughout the tutorial series has a distinctive,
consistent visual identity from the first chapter, instead of default framework styling.

**Why this priority**: Visual identity matters for the published tutorial, but the
repository is functional for development without it.

**Independent Test**: Can be fully tested by running the application and verifying the
rendered pages use the Violet Bloom color palette and typography in both light and dark
appearance modes.

**Acceptance Scenarios**:

1. **Given** the application is running, **When** the home page is viewed in light
   mode, **Then** the page renders with the Violet Bloom theme's light-mode palette
   rather than the framework's default styling.
2. **Given** the application is running, **When** the viewer's appearance preference is
   dark mode, **Then** the page renders with the Violet Bloom theme's dark-mode palette.
3. **Given** the theme is applied, **When** a new UI component is added using the
   project's component conventions, **Then** it inherits the Violet Bloom design tokens
   without per-component styling work.

---

### Edge Cases

- What happens when a `relay-tutorial` repository or a root-level `relay-tutorial`
  directory already exists? Setup must detect the collision and stop rather than
  overwrite existing content.
- What happens when a developer clones `relay` without initializing submodules? The
  `relay-tutorial` directory is empty; documentation must make the initialization step
  explicit so this is a known, recoverable state.
- How does the theme behave for a viewer with no explicit appearance preference? The
  application must fall back to a sensible default mode and remain fully themed.
- What happens if the latest Next.js version changes between specification and
  execution? "Latest" is resolved at creation time; the version actually installed is
  recorded in the repository's dependency manifest and becomes the pinned baseline
  (consistent with the tutorial plan's rule to pin versions early, risk T3).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: A repository named `relay-tutorial` MUST exist as an independent git
  repository with its own history, hosted under the same account/owner as the `relay`
  repository.
- **FR-002**: The repository MUST contain a Next.js application generated by the
  official Next.js scaffolding CLI, using the latest stable Next.js version available
  at creation time.
- **FR-003**: The generated application MUST NOT be hand-modified beyond theme
  application (FR-005), documentation (FR-007), and configuration required to run —
  the scaffold output is the baseline the tutorial builds on.
- **FR-004**: The `relay` repository MUST register `relay-tutorial` as a git submodule
  at the repository-root path `relay-tutorial/`, pinned to an exact revision, so a
  fresh clone with submodule initialization reproduces the application byte-for-byte.
- **FR-005**: The application MUST apply the Violet Bloom theme as its global visual
  theme, covering color palette, typography, and component design tokens, with both
  light-mode and dark-mode variants functional.
- **FR-006**: The application MUST start locally with the standard install-and-run
  commands documented in its README, rendering its home page without startup errors.
- **FR-007**: The `relay-tutorial` repository MUST include a README stating the
  repository's purpose (the application for the *Building Relay* tutorial series), its
  relationship to the `relay` repository, and how to install and run it, including the
  submodule initialization step for developers arriving via the parent repo.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A developer with a fresh clone of the `relay` repository can reach a
  locally running, fully themed tutorial application in under 5 minutes following only
  the documented instructions.
- **SC-002**: 100% of pages in the scaffolded application render with the Violet Bloom
  theme in both light and dark modes — no page falls back to default framework styling.
- **SC-003**: The Next.js version recorded in the repository matches the latest stable
  release available on the creation date.
- **SC-004**: Checking out any recorded revision of the `relay` parent repository and
  initializing submodules yields the exact matching revision of the tutorial
  application, with zero manual version coordination.

## Assumptions

- "Violet Bloom" refers to the publicly available community theme preset of that name
  (a shadcn/ui-compatible design-token theme); applying it includes installing the
  component/token conventions it depends on.
- The `relay-tutorial` repository is hosted on GitHub under the same owner as the
  parent repository (`anhba817`), and is public — the tutorial plan (§2) commits to a
  public tutorial home.
- Scaffolding CLI defaults are accepted (TypeScript, App Router, linting, Tailwind CSS)
  except where the theme requires a specific choice; exact prompts/flags are a planning
  decision.
- The submodule lives at the repository root as `relay-tutorial/`.
- This feature delivers the scaffold and theme only — no tutorial content, chapters, or
  Relay-specific application code are in scope.
- Creating the hosted repository (an outward-facing action) is authorized by this
  feature request; visibility can be adjusted later without rework.
