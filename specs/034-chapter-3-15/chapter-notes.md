# Chapter notes — what the plan said against what shipped

Two chapters, 21 phases, 251 tasks, 12 SRS clauses. This file records the difference between
the plan and the result, phase by phase, including the phases that went badly — a record that
only reports the plan working is one nobody trusts.

**The eighth is the one that mattered.** What a chapter *teaches* is not what it must *fence*.
Eleven files changed by exactly one word — a corrected chapter citation, zero substantive lines
— and the chain does not care why a file changed: a claimed path's state must equal the
repository's. Eleven fences with no subject.

T091 had found the inverse three phases earlier: `tenant-scope.itest.ts` is a **subject with no
fence**, because the catalogue's classification moved from 22 tables to 23 and the file did not
change by one character. Neither direction was in the assignment table, and both were found by
asking the repository rather than by reading the plan.

**What it cost:** 3.16's word estimate went from comfortable to binding. 26 taught files at the
series' measured 160 words each is 4,160 — over the 4,000 bound. Chapter 3.15 came in 8% under
its own estimate, which predicted ≈3,830 for 3.16; it landed at 3,800. **The estimate corrected
by one measurement was the one that worked; the nominal rate said the chapter could not be
written.**

## The phases that went badly

**Phase 8's T086 nearly asserted a defect as behaviour.** Three checks were removed in turn and
each failed its own attack; the temptation was to record "nothing masked" as a success. What
made it a real finding was asking *why*: the history path's outermost check **is** the
visibility check, because Phase 7 replaced `channelExists` rather than adding beneath it. Added
underneath — the obvious way — that removal comes back green and the suite reports success.

**Phase 12's T126 was passing while proving nothing.** The test sent a message, set the read
position to that message's sequence, and asserted zero. Green, and it demonstrated only that
the position can be written. The assertion that matters is the one *before* the acknowledgement,
and the spec's assumption — "a user's own message is read by them" — is false.

**Phase 13's T134 depended on the opposite of a recorded finding.** It awaited a
`message.created` frame in a gateway suite where none has ever arrived, because the api
publishes to no fan-out. Chapter 3.12 recorded that as its own finding and I wrote a test
against it. It timed out at 5 s and took a neighbouring suite's `beforeAll` down at 90 s, which
looked like a second failure and was contention.

**Phase 14's T144 deleted a shared fixture — the third time in this feature.** Two failures, one
cause, and the second looked unrelated. Phase 7 hit it twice. The fix is a fixture of its own,
never an ordering constraint, because an ordering constraint is invisible to whoever adds the
next test.

**Phase 19 read one `diff` hunk three wrong ways.** `diff -U0` said `@@ -360,0 +441,186 @@` —
one insertion. It was two blocks (61 lines belonged to the appendix, so taking all of them made
the chapter absorb an appendix hunk); `pre[:360]` dropped the predecessor's last three lines;
and `-360,0` is not the semantic insertion point. **A hunk says *a* way to get from one file to
another, not *the* way** — and when a second tool applies its own hunks to the result, which way
you chose is the whole question.

**And one page would not parse.** An indented `400  {"code": …}` block is literal text in
markdown and a JSX expression in MDX. The build failed with `Could not parse expression with
acorn` at line 3134 of a 4,400-line page.

## Two of my own defects, both in code that shipped nothing

**A SQL injection hole in the repository layer.** The first `removeMembers` built its `IN` list
with `sql.raw` from request-body ids, written while implementing a chapter about authorization.
Nothing in the lane would have caught it: every test passes ids that are already uuids.

**An `eslint-disable` I left alone on purpose**, and a lint warning that is still there.
`session.perf.itest.ts:120` carries a stale directive. Removing it is one line and would have
made the file the 41st in a measured count, for a cosmetic warning — so it is recorded instead,
for the next feature to touch that file.

## What the instruments caught that reading did not

    the derived target list    failed on the build that added each of six routes, before
                              anybody classified them — five separate times
    codes.test.ts             failed on the build that added close code 4003, which is
                              what made a fifth code a decision rather than an accident
    the coverage ratchet       failed on lines 98.92% against a pin of 99, and the fix was
                              to REMOVE a redundant throw rather than test it — the second
                              time this ratchet has deleted code instead of covering it
    the lint rule              refused a test importing drizzle-orm outside the repository
                              layer; the assertion moved suites and the rule was right
    check:fences               31 HEAD problems became 0, and the two APPLY problems it
                              raised were the only reason the appendix's anchor was found
    check:figures              did not exist. Fifteen figures in four published chapters
                              rendered a caption over nothing, and nothing was looking

**The one instrument that had to be built: `check:figures`.** `Figure` takes `caption` and
`code`; chapters 3.11 to 3.14 passed `chart={…}` and this chapter's first draft passed
`src={…}`. MDX props are not type-checked, so all three spellings build green and hand the
diagram `undefined`. Chapter 9's page emits four mermaid sources; chapter 13's emitted zero.

Found by comparing the two locales' props while translating. **And the checker's own first
version reported 122 problems in 193 figures** — every one a false positive, because chapters up
to 3.4 write `<Figure>` across three lines with the prop on the second. A checker that cries
wolf on a healthy tree is how a real problem hides.
