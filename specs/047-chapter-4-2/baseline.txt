T001 — CLICKHOUSE ANSWERS /ping AND REFUSES EVERY QUERY
-------------------------------------------------------
    $ curl -s "http://localhost:${RELAY_CLICKHOUSE_HTTP_PORT:-8123}/ping"
    Ok.

    $ curl -s "http://localhost:${RELAY_CLICKHOUSE_HTTP_PORT:-8123}/?query=SELECT+1"
    Code: 194. DB::Exception: default: Authentication failed: password is incorrect,
    or there is no user with such name. ... (REQUIRED_PASSWORD)

The premise holds, and the chapter's opening stands: the store has been in compose since
chapter 1.2, its health check has been green throughout, and nothing outside the container
could ever query it.

AND THE TWO HALVES DO NOT NAME THE SAME MECHANISM, which is worth writing down before the
prose does. The document says `default` is restricted to ::1 and 127.0.0.1 — that is a
NETWORK restriction, and T002 quotes it. What a caller from outside actually receives is an
AUTHENTICATION error naming a password. Both are true of the same refusal; only one of them
is what the reader will see in their terminal, and the chapter should show that one.


T002 — WHERE THE RESTRICTION LIVES
-----------------------------------
    $ docker compose exec -T clickhouse cat /etc/clickhouse-server/users.d/default-user.xml

    <clickhouse>
      <!-- Docs: <https://clickhouse.com/docs/operations/settings/settings_users/> -->
      <users>
        <default>
          <!-- User default is available only locally -->
          <networks>
            <ip>::1</ip>
            <ip>127.0.0.1</ip>
          </networks>
        </default>
      </users>
    </clickhouse>

It is in the IMAGE, not in this repository. Anyone who tries to fix `default` is editing
somebody else's file, which is why T009 adds a user instead.


T003 — SAD 6.2's DDL DOES NOT APPLY
------------------------------------
The statement was extracted from `docs/05-sad.md` and posted verbatim — not copied from
research.md, because quoting a quotation cannot establish that a published document is wrong.

    $ docker compose exec -T clickhouse clickhouse-client --multiquery < <the SAD's CREATE TABLE>

    Received exception from server (version 25.3.14):
    Code: 450. DB::Exception: Received from localhost:9000. DB::Exception: TTL expression
    result column should have DateTime or Date type, but has DateTime64(3, 'UTC').
    (BAD_TTL_EXPRESSION)

`TTL ts + INTERVAL 90 DAY` on a `DateTime64(3, 'UTC')` column is refused. It has been
published since the first draft. T047 amends it to `toDateTime(ts)`.
