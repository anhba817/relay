PHASE 1 — THE CONTROL, AND THE THREE TIMES IT CAUGHT ITS OWN TOOLING
--------------------------------------------------------------------------------

  snapshot.mjs   240 of 240 post-appendix paths byte-identical to relay-platform
  replay.mjs     644 states reproduced byte-exact through the merge machinery
                 242 paths, 0 conflicts, 0 drift, exit 0

THE CONTROL FOUND A BUG IN THE REPLAY TOOL ON ITS FIRST REAL RUN. snapshot.mjs
dumps the whole chain state after every chapter, so a path appears in every
chapter directory from its introduction onward. Reading "present" as "fenced by"
produced empty commits, and `git cherry-pick` refuses an empty commit — the
forced control came back with a conflict on nearly every path, at chapters as
early as 1.04. Fixed by counting a key only where its snapshot differs from the
previous key's. The state count fell 5,020 -> 644; the first figure was inflated
by unchanged repeats.

AND THE CONTROL ITSELF WAS WRONG TWICE BEFORE IT WAS RIGHT.

  1. `--order current` leaves every sequence untouched, so all 242 paths took a
     fast path and the control compared snapshots against copies of themselves.
     5,020 green states, zero lines of merge machinery exercised. `--force-replay`
     runs the merge regardless.

  2. The drift check then compared against replay's OWN INPUT. A corrupted
     snapshot was reproduced faithfully and the comparison passed. The target is
     now the platform file for the 193 paths the appendix does not amend — an
     independent one — and the pre-appendix snapshot for the 49 it does, counted
     separately rather than silently trusted.

FOUR PROBES WERE NEEDED TO MAKE THE CONTROL RED, AND THE FOUR ARE THE FINDING:

  perturb a mid-chain snapshot        green — the next delta cancels it
  perturb an appendix-amended path    green — its target IS the snapshot
  perturb the last-changing chapter   green — later directories hold the original
  perturb from that chapter onward    RED, exit 1, DRIFT infra.test.ts

So the control detects a wrong END state, not a wrong intermediate one. An
intermediate corruption that is later corrected is invisible to it. That is
defensible — the chain's contract is the end state plus every hunk applying — but
it is a limit, and it is recorded rather than assumed away.

REF is a three-branch alternation:

  one control for the whole pattern     break [Cc]hapter    exit 0 — the control
                                                            string still matched

                                                            branch
  a compiled pattern per branch         break REF's paren   exit 0 — the controls

  REF joined FROM named branches,       all five probes     all exit 1

A CONTROL ANOTHER BRANCH CAN SATISFY IS NOT A CONTROL FOR THE BRANCH IT NAMES.
Both broken designs looked correct on the page; only the probes told them apart.

  conflict, because there is no file to conflict with.

WHY MERGING CANNOT RESOLVE THE 14. Taking `theirs` at the first conflict only
relocates it — the creator's own "create this file" delta then meets an add/add
against the file it was meant to create. Re-sorting the old states does not work
either: the chain's final state is pinned to the platform file, and a state
sequence ending on the creator's OLD content makes the file shrink at the last
chapter. `catalogue.ts` is the clearest case, two chapters long:

    published   3.12 -> 3.23        base 176   ours 0   theirs 221
    target      3.23 -> 3.12

THIS IS R4'S PREDICTION ARRIVING WITHOUT THE INSTRUMENT IT NAMED. R4 said a
synthesised state that will not compile means the order violates a real
dependency, "a finding about the order rather than a bug in the tool". Found by
asking which side of the merge was empty, before any typecheck ran.
