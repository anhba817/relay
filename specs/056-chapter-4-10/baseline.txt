T001  ONE SERVICE, AND THE REGISTRY IS PART OF THE NAME

      `quay.io/minio/minio:latest`, 241 MB, `command: server /data`, a named
      volume, and the port behind `RELAY_MINIO_PORT`. `minio/minio` on Docker Hub
      is `pull access denied … repository does not exist or may require 'docker
      login'`, and `docs/05-sad.md:1002` has named MinIO without a registry since
      the first draft.

T001a THE API DEPENDS ON IT, WITH `condition: service_healthy`

      Beside postgres, nats and redis. NOT beside clickhouse, which is absent from
      that list because the api never touches it at boot; this store the api
      reaches on every slot request. Without the condition the first slot request
      can be refused with `media_storage_unavailable` for a startup reason —
      correct, and indistinguishable from a real outage.

T002  THE HEALTH CHECK AUTHENTICATES, AND IT WAS PROBED IN BOTH DIRECTIONS

      ClickHouse's check in the same file is the precedent: it runs a real query
      because `/ping` was green from chapter 1.2 to 4.2 while every query from
      outside the container was refused.

        the check as configured (mc alias set + mc ls)      exit 0
        the same with a WRONG password                      exit 1
            mc: <ERROR> Unable to initialize new alias from the provided
            credentials. The request signature we calculated does not match
            the signature you provided.
        /minio/health/live, unauthenticated, from the host  HTTP 200

      **The liveness endpoint answers 200 to a caller with no credentials at all**,
      which is the ClickHouse shape exactly. `mc` is in the image; `wget` and `nc`
      are not, so this is the available way to ask a question only a working store
      can answer.

      Container reached `healthy` and stayed there, failing streak 0.
