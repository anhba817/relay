## Findings the plan did not anticipate

### 1. The blast radius was 11 files, not 8 — and the FENCE radius was 29

The plan measured `x-relay-environment` and found eight files. It missed three
production files that carry the seam without naming it: `messages.controller.ts`
and the two internal controllers, which used `EnvironmentContextGuard` and the
paired `x-relay-user` header. Measuring one string is not measuring a seam.

The larger surprise is downstream. Twenty-nine files that earlier chapters had
fenced were changed by the two retirements, and `check-fence-chain`'s HEAD rule
requires the chapter that changes a fenced file to amend it. So chapter 3.2
carries **41 fences** where 2.7 carried 15. Nothing was wrong with the rule; the
plan simply never costed it. Any future chapter that retires a seam should
budget the fence work at planning time — the code change is the cheap half.

### 2. The fence chain had no story for deletion

This is the first chapter to delete a fenced file. The checker could only report
"does not exist in relay-platform" — the same message a genuine mistake
produces. Added a `(deleted)` title form: the chain ends for that path and the
check inverts, so the file must be **absent**. A deletion that did not happen is
now as loud as an amendment that did not.

### 3. base64url contains the separator

`data-model.md` said the credential splits on the last underscore. Both halves
were base64url, whose alphabet includes `_`, so no split position is safe. Fixed
by making the public id hex (fixed length, no `_`), which costs nothing —
the handle is not a secret and does not need the density. Caught by the first
mint, before anything was published. It became the chapter's first TRAP.

### 4. FR-AUT-11 is half-true, and the honest half is now visible

An established socket outlives its token — verification happens at connect, and
that is tested. But the internal hop forwards the same token, so a socket that
outlives its token can still **receive** and can no longer **send**. Rather than
surface that as `internal_error`, the socket answers with a message naming the
recovery ("reconnect with a fresh one to send again"). FR-AUT-11's second clause
— handing over a refreshed token on the open connection — needs a protocol
frame, which belongs with the SDK in Part 5. The test asserts the refusal
explicitly, so the gap is a documented behaviour rather than a surprise.

### 5. Two rules of the codebase caught me, correctly

- `credentials.itest.ts` imported drizzle's `sql` helper. The lint rule keeps
  the query engine inside the repository layer (constitution I, ADR-16) and does
  not exempt tests. Rewritten to `db.execute` with a plain string, which is what
  `signup.itest.ts` already did.
- `ApiError` used a constructor parameter property. The api released
  `erasableSyntaxOnly` in 1.4; the gateway did not. Field declared explicitly.

Both were invisible to a `grep -E "error"` over the gate's output and appeared
only when the exit codes were checked. Grepping a build log is not running a
gate — worth remembering.

### 6. Research R11 was wrong about the Vietnamese 3.1

R11 recorded "only the English 3.1 exists, so it is a one-file edit". A
Vietnamese 3.1 does exist — it was translated after Phase 0 was written — and it
carried the same false forward reference ("Không session — đó là việc của 3.2").
Both locales are corrected, and both carry a REVISED note about the signup
response gaining a key. **The Vietnamese wording is a two-sentence correction to
an existing translation and should be reviewed by the translator**, since this
feature is otherwise English-only.

## Standing debt this chapter did not create but is now blocked by

names a state (`part2-ch5` … `part3-ch2`) that cannot be checked out, and the
rebase recipe in `specs/019-stack-refoundation/rebase-recipe.md` now needs
states for 2.2–2.8, 3.1 and 3.2 appended. The fence chain proves the chapters
replay onto HEAD; it cannot prove a reader can reach an intermediate state,
because those states do not exist yet.
