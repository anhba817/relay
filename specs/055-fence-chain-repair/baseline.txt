T008  the 109 -> 110 discrepancy (FR-014) — RESOLVED, AND THE FILE IS NAMED

        045 closed reporting 109 (APPLY 74, HEAD 35) with the unpatched gate.
        046's T006 opened at 110 (APPLY 74, HEAD 36) and blamed a relay-tutorial
        commit: "the tutorial repository moved to 0f4d8d6 since; APPLY is unchanged."

        Vietnamese translations, and a vi commit cannot add a HEAD problem —
        the HEAD loop iterates en.state only (050-3).

        The cause is in relay-platform. In the window rework/part3-ch26..part4-ch1,
        exactly two of the 25 divergence targets were touched, and one of them is
        .gitignore:

                      prose never enforced

        Chapter 1.1 publishes .gitignore as a whole body of 7 lines. The tree became
        8. HEAD 35 -> 36, total 109 -> 110.

        So the 110th problem is NOT inherited from Part 3. It is feature 046's own,
        created by the seeder work in the same feature whose T006 first reported the
        new number — and 046 read the change as the tutorial moving, because the
        delta-of-0 convention compares a total to a total and never asks which file.

        Every chapter since has measured against 110 and called the delta 0.
